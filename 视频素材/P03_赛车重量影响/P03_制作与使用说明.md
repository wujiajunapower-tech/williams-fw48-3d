## 剪映专业版中的建议方式

1. 建立 1920×1080、30fps 的横屏项目，把真实比赛素材放在下层。
2. 将三条 **MOV** 导入素材库，放在比赛视频上方的视频轨道。保留原始尺寸／100% 缩放，使用普通／默认合成方式和 100% 不透明度，让文件自身的 Alpha 控制透明。
3. 按旁白起点分别放置 A、B、C，默认片长为 7、7、8 秒。字幕使用独立轨道，放在 y914–1004 的预留区域。预览 MP4 只供看片，不作为透明素材叠加。
4. 正常导入并识别 Alpha 时无需抠黑、色度抠像或滤色。先用一条明亮镜头和一条暗镜头回放检查文字边缘。实际镜头构图改变时，可以挑选中央留空的镜头，或在源工程调整左右图形位置后重渲染。

本次已验证 MOV 的编码与真实透明像素，尚未在用户当前安装的剪映版本中进行导入测试。若该版本没有正确读取 ProRes Alpha，保留原 MOV，并可运行下方 PNG 备用序列命令，交给支持 Alpha 的后期流程处理；不要把预览 MP4 当作透明版。

## 实时预览和重渲染

在 `williams-mg` 目录双击 `启动预览.command`，或运行：

```bash
./run.sh preview
```

打开 http://localhost:3100 ，选择 `P03-Weight-Overlays` 文件夹。`P03-A/B/C` 是透明版，可打开 Studio 棋盘格查看；`P03-A/B/C-Preview` 是模拟叠加预览；`P03-Demo` 为三段顺序播放。拖动时间线逐帧检查，修改代码后自动刷新。

预览属性 `tone` 可选 `bright`／`dark`，`showGuides` 控制字幕参考框，`showOverlay` 可临时隐藏技术层；`reducedMotion` 提供轻运动版本。正式交付用完整运动版本，所有动画都由 Remotion 帧数驱动。

```bash
./run.sh p03 all           # 透明 MOV、三个 MP4、22秒演示
./run.sh p03 P03-A         # 只渲染加速透明 MOV
./run.sh p03 P03-B         # 只渲染制动透明 MOV
./run.sh p03 P03-C         # 只渲染过弯透明 MOV
./run.sh p03 alpha         # 只渲染三条透明 MOV
./run.sh p03 previews      # 只渲染四条 MP4
./run.sh p03 stills        # 关键帧和明暗背景检查图
./run.sh p03 png           # 三段完整透明 PNG 备用序列
./run.sh check             # TypeScript 检查
./run.sh verify-p03        # FFprobe、解码、Alpha 与旧项目检查
```

也可运行 `pnpm render:p03`、`pnpm render:p03:alpha`、`pnpm render:p03:previews`、`pnpm stills:p03`、`pnpm verify:p03`。没有新增 npm 依赖。首次移到新电脑需安装 Node.js、pnpm，并执行 `pnpm install --frozen-lockfile`，首次渲染允许 Remotion 下载浏览器。字体仍由锁定的 Fontsource 依赖本地提供，保留原字体许可。

时间以帧存储，`seconds(5)` 即 150 帧。主要节奏为：标题与条件 0–2 秒，机制示意 2–5 秒，结论 5 秒起；A/B 最后 0.4 秒退出，C 同样在最后 0.4 秒退出。结论完整可读的停留约为 A/B 1.5 秒、C 2.5 秒，已配合简短文字及前面的条件解释。需要配合较慢旁白时，应同时延长 `P03_LENGTH` 和对应结论／退出时间，再完整重渲染；片长改变后还需更新渲染、验证脚本内预期帧数。

颜色从已有 `src/project.ts` 读取，P03 独立覆盖在 `P03_COLOR`。只想调整本段时修改 P03 的覆盖值，避免影响 G01/G02。中文使用 Noto Sans SC，英文小标使用既有 Barlow Condensed。沿用 `src/motion.ts` 的曲线和小幅 spring，正文数据不弹跳。

## 物理口径与使用限制

- 加速：在其他条件相同、同一净驱动力下，以 `a = F净 / m` 解释不同质量的响应。两条输入力箭头等长，响应箭头和位移只作相对关系示意，不能解读为质量比或实际加速度。
- 制动：同一速度下使用 `Eₖ = ½mv²` 解释动能与能量管理需求。能量条、制动盘和热负荷箭头没有温度刻度、真实能量值或固定制动距离增幅，也没有宣称所有能量只由单个制动盘吸收。
- 过弯：同速同半径下使用 `Fᵧ = mv²/r` 表示所需横向力，箭头始终沿曲率方向指向弯心。轮胎负荷与抓地响应分开表达，指出负荷敏感性及其他轮胎条件；没有用两条不同路线暗示重车必然冲出弯道。
- 全部为屏幕固定位置的工程示意，不追踪实拍赛车，不模拟真实轮胎模型、侧倾或动态载荷转移。实拍赛车若横跨左右图形区域，仍需通过选镜头或改布局解决。
- 中央 x560–1360、y310–840 保持透明，底部 y914–1004 保持透明。标签与结论集中在上部，左右分别承担解释图形，脚注位于 y862 附近。

## 实测验收

`exports/P03/P03_媒体与透明通道检查.json` 保存每条文件的编码、帧数、时长及 Alpha 检查结果。三条 MOV 的所有帧均解码为 RGBA，在 480×270 检查保护区域；另对第 110 帧做 1920×1080 完整像素检查。首尾帧全透明，中央及字幕区 Alpha 最大值为 0。三条素材都同时存在全透明、半透明和不透明像素，非黑底冒充。

编码设置为 `prores`、`proResProfile: '4444'`、`pixelFormat: 'yuva444p10le'`、`imageFormat: 'png'`，与 [Remotion 官方透明视频说明](https://www.remotion.dev/docs/transparent-videos)一致。FFprobe 读取时显示 `ap4h`、profile `4` 和 `yuva444p12le`，这是本机解码器对 ProRes 4444 的表示；已进一步读取实际 Alpha，未仅凭编码名称判断透明。

`qa/p03/P03-decoded-MOV-contact-sheet.jpg` 是从导出的 MOV 解码后，重新叠加亮、暗占位背景的六格检查图。`qa/p03/P03-composite-check.json` 记录解码成片与源图合成的平均 RGB 误差，六组均小于 0.06／255。`qa/p03/` 同时保留入场、解释、结论和退出关键帧；中文均完成视觉检查。

已通过 TypeScript 检查。G01/G02 源文件、共用主题／运动／字体组件及三条既有 MP4 的 SHA-256 均与制作前一致；入口只追加 P03 注册，旧渲染命令仍保留。

# 模式升级实施与验收记录

中央视口布局：
```text
┌ 原品牌栏 ─────────────────────────────────────────┐
│ 原左侧文案 │ 3D 赛车（原 GLB / 灯光 / 渲染）│ 原技术面板 │
│           │ 原自动镜头 / 复位 / 聚焦 / 分解 │           │
│           │ 五色图例（仅气流）             │ 五组开关  │
│           │                              │ 透视/说明 │
│           │ [气流可视化] [部件解析]        │           │
│           │ [Explore] [Drive] [Aero]       │           │
└───────────┴──────────────────────────────┴───────────┘
```

- 移除页面底部 transport、timeline、time、播放倍率和章节 seek。
- 模式调度无总时长；28 秒仅为 Drive 周期，并非页面时间轴。
- 仅一套相机控制/渲染循环。手动 OrbitControls 接管、自动跟随与复位互斥；过渡从当前 pose 开始。
- 材质的 baseMaterial 不修改。聚焦和透视在一个组合函数中计算，可平滑恢复。
- 累计 distance 贯穿模式，轨道坐标包裹；包裹点位于远景，车型不做屏幕左右往返。
- 保留卡钳静止、轮胎轴心、主动翼片和全部分件标签。
- UI 状态属性与按钮选择器需明确作用域，避免 data-mode / data-aero-view 匹配 body。
- 发现并修正环绕矩阵符号错误；数学测试覆盖整个周期间的恒定半径。
- 最终证据以 test-results/modes/*report.json 和对应截图为准，不以构建成功代替视觉验证。

开发服务验证备注：浏览器可能取消 Vite 预打包模块请求（net::ERR_ABORTED）。测试仅允许这种开发模块取消，并要求同一 URL 重取为 200 且具有有效响应内容；其他失败仍会中止验证。生产构建检查严格要求无 HTTP / 脚本 / 着色器错误。以 production-report.json 判断交付加载结果。
